# docs-automation-study

Учебный репозиторий по практической работе 3.4 «Автоматизация разработки технической
документации: от хаоса к конвейеру».

Документация ведётся по принципам **Docs-as-Code**: исходники хранятся в текстовом
виде рядом с кодом, версионируются в Git, проходят автоматическую проверку и
публикуются на GitHub Pages тем же конвейером, что и любая сборка.

## Что внутри

| Каталог | Назначение |
| --- | --- |
| `docs/` | Исходники документации в Markdown |
| `diagrams/` | Схемы как код (PlantUML) и результаты их рендера |
| `openapi/` | Спецификация REST API в формате OpenAPI 3.1 |
| `swagger/` | Swagger UI для интерактивного просмотра спецификации |
| `tools/` | Сборочный скрипт и линтер документации |
| `.github/workflows/` | Конвейер CI/CD: проверка, сборка, публикация |

## Публикация

Каждый коммит в ветку `main` запускает workflow `docs.yml`: линтер, сборка и
выгрузка каталога `site/` на GitHub Pages.
