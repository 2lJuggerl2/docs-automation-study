# Архитектура

## Схема компонентов

Схема хранится как код в файле `diagrams/component.puml` и рендерится в SVG при
сборке. Изменение архитектуры начинается с правки диаграммы, а не с правки картинки в
редакторе.

![Схема компонентов](diagrams/component.svg)

## Компоненты

- **Веб-клиент** — одностраничное приложение для преподавателя и студента.
- **API-сервис** — REST-слой на FastAPI, отдаёт JSON и валидирует входные данные по
  схеме Pydantic.
- **Хранилище** — PostgreSQL, три основные таблицы: `students`, `works`, `submissions`.
- **Отчётный модуль** — формирует CSV по расписанию и по запросу.

## Поток данных при сдаче работы

1. Клиент отправляет `POST /api/v1/submissions` с идентификаторами студента и работы.
2. API проверяет существование обеих сущностей и отсутствие дублирующей сдачи.
3. Запись сохраняется со статусом `submitted`.
4. Преподаватель выставляет оценку через `PATCH /api/v1/submissions/{id}`.
5. Отчётный модуль при следующем запуске подхватывает оценённые записи.

## Принятые решения

| Решение | Обоснование |
| --- | --- |
| REST вместо GraphQL | Набор запросов фиксирован, выгода от гибких выборок отсутствует |
| PostgreSQL | Нужны транзакции и внешние ключи между тремя таблицами |
| OpenAPI 3.1 как источник истины | Спецификация и Swagger UI собираются из одного файла |
| Диаграммы в PlantUML | Текстовый формат даёт осмысленный diff в Git |
