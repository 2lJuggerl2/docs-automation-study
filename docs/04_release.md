# Сборка и публикация

## Принцип

Документация — это исходный код. Она лежит в Git рядом с диаграммами и схемой API,
проходит проверку в конвейере и публикуется на GitHub Pages автоматически. Руками
на сервер не копируется ничего: единственный способ изменить сайт — сделать коммит.

## Структура репозитория

```text
docs-automation-study/
├─ docs/                 исходники страниц в Markdown
├─ diagrams/             схемы PlantUML и результаты их рендера
├─ openapi/openapi.yaml  спецификация REST API
├─ swagger/              статика Swagger UI
├─ tools/build.mjs       сборщик сайта
├─ tools/check.mjs       линтер документации
├─ .github/workflows/    конвейер GitHub Actions
└─ site/                 результат сборки (в Git не хранится)
```

## Сборка локально

```powershell
npm install
npm run check
npm run build
npx serve site
```

`npm run check` проверяет ссылки, заголовки и наличие файлов, на которые ссылаются
страницы. `npm run build` собирает `docs/*.md` в `site/*.html`, копирует статику,
диаграммы и Swagger UI и кладёт в корень `site/` пустой файл `.nojekyll` — без него
GitHub Pages отбросит каталоги, начинающиеся с подчёркивания.

## Конвейер GitHub Actions

Конвейер описан в `.github/workflows/docs.yml` и срабатывает на каждый push в `main`:

1. **checkout** — получить содержимое репозитория.
2. **setup-node** — поставить Node.js 20.
3. **npm ci** — установить зависимости строго по `package-lock.json`.
4. **npm run check** — если проверка не прошла, сборка останавливается и правка не
   попадает на сайт.
5. **npm run build** — собрать `site/`.
6. **upload-pages-artifact + deploy-pages** — опубликовать каталог `site/`.

## Ветки и ревью

- Работа ведётся в ветке `main`; крупные правки — в отдельных ветках с pull request.
- В pull request видно diff Markdown и diff диаграмм: изменение схемы PlantUML
  читается как текст, а не как «картинка поменялась».
- Автор правки и проверяющий — разные люди, даже если это учебный проект: роль
  проверяющего играет второй участник или преподаватель.

## Версионирование

Версия документации совпадает с версией продукта и хранится в `package.json`.
История изменений ведётся в `CHANGELOG.md`; запись добавляется в том же коммите, что
и правка документации.

## Что даёт конвейер

| Было | Стало |
| --- | --- |
| Документ в Word пересылается по почте | Документ в Git, история правок видна построчно |
| «Финальная_версия_2_испр.docx» | Ветка и коммит с осмысленным сообщением |
| Схема нарисована в редакторе и потерялась | Схема — текст `diagrams/*.puml` в репозитории |
| Спецификация API расходится с кодом | Swagger UI собирается из `openapi.yaml` при каждой сборке |
| Публикация — ручное копирование на сервер | Публикация — push в `main`, остальное делает конвейер |
